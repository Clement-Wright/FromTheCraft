# FromTheCraft

Convert structures between From the Depths `.blueprint` files and Minecraft Java 1.21.1 Create `.nbt` or Litematica `.litematic` files. Compare the source and converted structure in linked 3D views, then export the file behind the converted preview.

FromTheCraft runs locally on Windows. It converts hulls, decks and building materials; moving parts become static geometry, and gameplay systems don't carry across. Exported files have format checks, but loading them in Minecraft/Create, Litematica and From the Depths remains unverified.

![FromTheCraft showing the included demo hull, linked previews, a hovered block and material counts](docs/images/workbench.png)

## Download and run

1. Open the [latest Windows release](https://github.com/Clement-Wright/FromTheCraft/releases/latest) and download the Windows ZIP under Assets. The current release is [v0.2.0](https://github.com/Clement-Wright/FromTheCraft/releases/tag/v0.2.0).
2. Extract the entire ZIP to a folder. GitHub's autogenerated **Source code (zip)** contains the source only; use the Windows release asset to run the app.
3. Open `FromTheCraft.exe` in the extracted folder. Keep the whole folder together, including its support files. You don't need to install Python or Node.

The launcher opens your browser on a free loopback port. Conversion stays on your computer, with no accounts, analytics, CDN assets or external network calls. Use **Close app** to stop the service, or close the browser tab and let it stop after three minutes without a browser heartbeat.

Try the included [demo hull](examples/demo-hull.blueprint) if you want a small starting file. The [examples folder](examples) also contains its NBT and Litematic exports. These examples were authored for FromTheCraft and use the project's license.

## Convert a structure

Open or drop a `.blueprint`, `.nbt` or `.litematic` file. For an FtD source, choose **Create NBT** or **Litematic**; Minecraft sources convert to **FtD blueprint**. Choose the output scale and, for Minecraft output, a material preference: **Balanced**, **Material first** or **Color first**.

Click **Convert**, inspect both views and read the conversion notices, then click **Export file**. Hover over either preview to see the block name, material, state and comparison origin. You can also focus a viewer and press **I** to inspect its center. These coordinates describe the displayed primitive's origin, which can differ from an FtD block's saved anchor.

The **Build materials** list counts source parts or exported blocks; a 4 m source beam counts as one part. The converted list counts the actual serialized blocks, grouping their facing and other placement states under the same block name. Search the list or collapse it to give the previews more space. Linked cameras help you check the same area in both views. Changing the source or conversion options clears the previous export until you convert again.

All five scales work in both directions: 4×, 2×, 1×, 0.5× and 0.25×. At 1×, one Minecraft block equals one FtD meter. Smaller scales merge occupied cells and can remove small openings or thin details. Estimated dimensions appear before conversion; large 4× results may exceed the limits below.

**Hollow interior** is optional and off by default. Set a shell thickness of 1 to 4 output cells to keep a shell along surfaces that face outside air. Air reaches inward through openings, so the shell can follow open passages. Enclosed interior decks and parts may disappear when you enable hollowing; existing empty cells stay empty. Review the converted preview before exporting.

## How conversion works

The source preview uses native structural primitives independently of the target grid. FtD beams occupy their full footprints, and nested child transforms compose continuously before the converter samples the geometry at the selected scale. Moving constructs become static geometry. Existing empty interiors stay empty; with hollowing off, conversion keeps internal decks rather than filling cavities. The first occupied contribution wins when parts overlap.

After sampling, the converter assigns building materials and writes the target format. It reads those exact bytes back to make the converted preview and caches them for export. The download therefore contains the same serialized result you inspected, without running another conversion.

Native FtD slopes, wedges and corners use distinct convex shape definitions. Their local direction comes from checks against installed game meshes; the source viewer and converter share those definitions. Axis-aligned Minecraft output can use stairs and slabs. Minecraft stairs become ordinary FtD slopes at 1×. Half slabs become 1 m blocks at that scale, while 2× preserves their half-height geometry. FtD paint uses RGB blended by its saved paint-strength channel; glass transparency follows the material class. Previews use flat colors and simplified geometry instead of game textures. Cross-game round trips lose detail.

## Conversion limits

Mimics and recognized decoration overlays are skipped. Special blocks receive inert approximations or documented omissions, with aggregated notices. Fluids, entities, stored item inventories and gameplay payloads are ignored. There is no machinery, physics, mimic reconstruction or Aeronautics assembly. Unknown modded blocks use reported inert placeholders.

Minecraft input must have data version **3955**, for **Java 1.21.1**. Other versions receive an error; there is no data fixer. The version-pinned registry contains 1,060 IDs, each with a mapped, approximated or skipped family policy. These policies do not promise exact appearances. Litematic input supports multiple offset regions and signed dimensions.

FtD output follows the inspected **3.8.5.11** blueprint schema, also checked against installed blueprint schemas saved by 4.2.5.2 and 4.3.1.11. The bundled MIT catalog is a fallback, with versioned native-shape corrections for ambiguous IDs. When available, FromTheCraft reads the installed game's `Core_*` item metadata and inherited beam footprints locally. This was checked against **4.3.4.0 build 1**, including stock blueprints. Set `FROMTHECRAFT_FTD` to the game folder or `StreamingAssets` folder for another installation. The older bundled catalog omits some newer IDs when the game isn't installed; the app reports those omissions. No game files are copied or bundled. Ordinary curved-hull shapes and thin plate slopes still use limited approximations. FtD version compatibility and in-game acceptance need further checks.

Limits are 32 MiB per uploaded file, 128 MiB decompressed NBT, 500,000 occupied output cells, 2,048 cells per axis, and an 8,000,000-cell bounding volume.

## Development

Use Python 3.12 and Node 22 or newer on Windows. From the repository folder:

```powershell
uv sync --python 3.12 --extra dev
Set-Location ui
npm.cmd ci
npm.cmd run build
Set-Location ..
.venv\Scripts\python -m fromthecraft
```

Tests and Windows packaging:

```powershell
.venv\Scripts\python -m pytest
.venv\Scripts\ruff check src scripts tests
.venv\Scripts\python -m fromthecraft --no-browser --port 8765
# In another terminal:
Set-Location ui
npx.cmd playwright install chromium
npm.cmd test
# From the repository folder:
powershell -ExecutionPolicy Bypass -File scripts\build_windows.ps1
```

Optional browser fixtures use `FROMTHECRAFT_SHIP` for a 1.21.1 `.nbt`, `FROMTHECRAFT_FTD_SHIP` for a stock FtD blueprint, `FROMTHECRAFT_HARD_SHIP` for a large, nested FtD blueprint, and `FROMTHECRAFT_SLOPE_SHIP` for the aircraft slope regression. Supply your own files; third-party ships are not distributed. Build on Windows; PyInstaller does not cross-compile a Windows executable from Linux. The build writes `dist\FromTheCraft\FromTheCraft.exe` and its support files.

The CLI uses the same engine and refuses to overwrite an existing destination:

```powershell
.venv\Scripts\python -m fromthecraft convert input.blueprint output.nbt --scale 0.5 --palette balanced
.venv\Scripts\python -m fromthecraft convert input.litematic output.blueprint
.venv\Scripts\python -m fromthecraft convert input.blueprint shell.nbt --hollow --shell-thickness 2
node scripts\verify_nbt.cjs output.nbt
node scripts\verify_litematic.cjs output.litematic # compares with sibling output.nbt
```

Read [development evidence](docs/implementation.md) for fixture provenance, measured checks and unverified behavior. Report reproducible problems in [GitHub issues](https://github.com/Clement-Wright/FromTheCraft/issues), including the input format, output format, scale and conversion notices. Share source blueprints only if you have permission to distribute them.
